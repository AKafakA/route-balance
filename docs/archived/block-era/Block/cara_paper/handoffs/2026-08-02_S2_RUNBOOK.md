### ⚠ The Q1 pilot may legitimately refuse at the 532 preset — read this before reacting

The driver runs **one cell per arm and asserts they differ** before committing the other 22. If
that pilot reports

> the arms agree on 100.00% of routing decisions … they are the SAME configuration

**do not conclude the static arm is inert.** Check the arm's TPOT table first: the static arm
should show **1 distinct value per tier** and the learned arm hundreds. If it does, the
configurations differ and only the *outcome* is identical.

**When that happens it is structural, not a bug.** Quality is minmax-normalised across the
candidate set, so when the set holds only two quality levels the quality winner takes a lead of
exactly `w_quality`, while the challenger's ceiling is `w_latency + w_cost`. At the 532 preset
those are **0.5 and 0.5** — the challenger can at most tie, so the TPOT estimator has zero
leverage and the arms are provably identical. At **uniform** they are 0.33 against 0.66 and the
estimator can flip decisions. Measured 2026-08-02 on a two-model fleet: 532 gave 100% agreement,
uniform (the Aug-01 run) gave a 2.6–3.9 pp shift.

On the full four-tier fleet minmax spreads quality across intermediate values, so the winner's
lead is normally well below 0.5 and 532 keeps its leverage — which is why the runs behind the
posted table did show a difference. **The pilot is the test; two cells decide it.**

If the pilot refuses at 532 on the production fleet, that is an author decision, not a
workaround: the uniform preset is already in the block and is in the regime where the
comparison is meaningful.

## 3. If it stops

**It stops on purpose.** Do not work around a phase — that rule exists because working around
one is what invalidated three previous campaigns. Read the `[STOP]` block; it names the phase
and the resume command.

The stops most likely to fire, and what each means:

* **`ORPHAN GATE FAILED`** — something is already running on one of the hosts in the
  *freshly derived* `hosts_all`. Nothing was launched. On a clean reprovisioned lease this
  should not fire; if it does, something is genuinely running there and needs looking at
  before any cell. (It fires today only because the current file still lists the rehearsal
  lease — see §5.)
* **`G-TIERS`** — the predictor loaded a tier not in the deployed fleet (the P100 zombie class).
* **`no rspec in …`** — §0 item 1 was skipped.
* **`the fleet monitor could not be restarted after 3 attempts`** — usually ssh from the VPS to
  the head node is broken. To proceed **knowingly without contamination monitoring**, export
  `MONITOR_OPTIONAL=1`.
* **A short rate** — the rate is left **unmarked** so a resume retries it, and the sweep
  continues so the window is not burned. `logs/SHORT_RATES.txt` lists them; their Phase E′
  verdicts are **provisional**.

## 6. Analysis, after the cells

```bash
python3 v3_scripts/dominance.py --cells <rate-dir> --lambda <N> --suggest      # Phase E'
python3 v3_scripts/burst_analysis.py --cells <burst-dir>                        # paired, t(5)
```

`dominance.py` **refuses** rather than guessing: unparseable cells, sub-100 % coverage, mixed
caps, a >12 h provenance span, a `REHEARSAL` marker without `--rehearsal`, or no matching cells
all exit 2. The driver now checks that exit code — an absence of "NOT DOMINATED" is no longer
read as dominance.

**Phase E′ is advisory, not adaptive:** it prints a suggested fill tuple; **no fill cell is ever
launched automatically**, and if one is run by hand it **must be labelled interpolated** in any
table.
