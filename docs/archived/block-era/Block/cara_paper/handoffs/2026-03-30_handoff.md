## Prediction Framework Design (Paper)

### Current (deployed):
| Signal | Method | Filter | Score |
|--------|--------|--------|-------|
| Budget | 16 bucket classifier | P(tokens ≤ B) ≥ θ (confidence) | E[length] from distribution |
| Quality | Reference_score regression | threshold (MAE ~0.16) | point estimate |
| TTFT | XGBoost per-instance | threshold + tiered relaxation | point estimate |
| TPOT | XGBoost per-instance | threshold + tiered relaxation | point estimate |

### Planned extensions:
| Signal | Extension | Status |
|--------|-----------|--------|
| Quality | 10-class classifier → P(quality ≥ min) ≥ θ + argmax scoring | Can use existing judge_class model |
| Quality labels | Prometheus reference-grounded judging (merge ref_score + judge) | Run on Vast after eval (~3-6h) |
| TTFT/TPOT | Quantile regression or conformal prediction | XGBoost supports natively, train on existing 405K data |

### Key design insight:
- **Length**: expectation E[length] for scoring (continuous multiplier for cost)
- **Quality**: argmax class for scoring (most likely outcome for model comparison)
- Both use CDF for filtering (accumulated probability ≥ confidence threshold)
- Same encoder, same architecture, different aggregation per signal type

## SLO Enforcement Discussion (for paper §3 and §6)

### The Problem
All prediction-based SLO systems face false filtering: prediction error near the SLO threshold causes good requests to be rejected or bad requests to pass. This affects TTFT, TPOT, and quality filtering.

### How Existing Papers Handle It

**QLM** (Queue Management, arXiv 2407.00047):
- Models total output tokens as Normal distribution via CLT
- Uses conservative upper-bound estimates for SLO checking
- Problem: Normal assumption is wrong for multi-dataset workloads (multi-modal distribution). Variance unknown at prediction time — estimated from queue which is a moving target.
- Reactive: re-triggers scheduler when violation predicted, reorders virtual queues

**SLOs-Serve** (Multi-SLO, arXiv 2504.08784):
- Proactive soft admission control: check if SLOs are attainable BEFORE accepting request
- Uses profiled roofline model (point predictions, R²=0.82-0.93)
- Declines unattainable requests upfront → guaranteed SLO for admitted requests
- Dynamic adjustment: tightens SLO mid-generation if request falls behind
- Problem: false rejections guaranteed — good requests declined based on imperfect prediction

**PolyServe** (Multi-SLO at Scale, arXiv 2507.17769):
- Deadline-based SLO: i-th token must arrive before TTFT + i×TPOT (cumulative, not per-token strict)
- Key insight: misprediction on one iteration can be compensated by faster future iterations
- Request binning: separate queues per TPOT tier, dedicated server clusters per tier
- Problem: outlier prediction errors cascade — one badly mispredicted iteration shifts ALL subsequent token deadlines

**Mooncake**: Simple prediction-based early rejection before processing
**PARD**: Proactive dropping mid-generation to save GPU on doomed requests (16-176% goodput improvement)

### Our Approach (RouteBalance)
- Point estimation (XGBoost TTFT/TPOT, 1.2-6.2% MAPE) + tiered constraint relaxation
- Closest to SLOs-Serve's soft admission but more granular: relax one constraint at a time in user-specified order (TTFT → TPOT → quality → budget)
- Every request gets served (no hard rejection) — just possibly at a suboptimal instance
- Comparable to state of the art for SLO enforcement

### Gap in the Literature
Nobody properly handles prediction uncertainty for SLO enforcement. All assume predictions are "good enough" with heuristic safety nets:
- QLM: assumes Normal distribution (wrong for heterogeneous workloads)
- SLOs-Serve: binary accept/reject (no confidence level)
- PolyServe: hopes errors cancel (fails under sustained load)
- PARD/Mooncake: no uncertainty modeling

### Our Unified Probabilistic Framework
We already demonstrate confidence-based filtering for budget (bucket classifier → P(tokens ≤ B) ≥ θ). The same approach extends to all signals:

| Signal | Current | Extension |
|--------|---------|-----------|
| Budget | Bucket classifier → CDF filtering ✅ | Already deployed |
| Quality | Point regression | 10-class classifier → P(quality ≥ min) ≥ θ, argmax for scoring |
| TTFT/TPOT | Point XGBoost | Conformal prediction: use empirical error distribution from validation set for prediction intervals. Or quantile regression (XGBoost native support) |

Key insight: classification produces richer output than regression for scheduling.
- Regression: one number
- Classification: probability distribution → supports both confidence-based filtering (CDF) AND point estimation (expectation or argmax)
- Operator chooses aggregation per signal: expectation for continuous (length→cost), argmax for categorical (quality→model selection)

### Conformal Prediction for TTFT/TPOT (Future Work)
- Train XGBoost on 80% of 405K latency data, compute residuals on 20%
- Per-instance error quantiles (A100 more predictable than P100)
- At serving time: `predicted_ttft + margin ≤ SLO` where margin = α-quantile of historical residuals
- Distribution-free: no Normal assumption. Coverage guarantee from conformal prediction theory.
- Simple to implement: one line change in filter + calibration table per instance type
- Would be genuinely novel in LLM serving SLO enforcement
