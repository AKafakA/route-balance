**Topology:** Prefill=node2 10.10.1.3:7100 (kv_producer); Decode=node3 10.10.1.4:7200 (kv_consumer); NIXL port 14579; P-D scheduler = node2:8200.

### Single-request smoke
```json
{
  "success": true, "output_tokens": 16,
  "ttft": 0.0521,                    // = prefill_ms/1000
  "itl": [],                         // ⚠ empty for P-D — Day 3.2 gap
  "server_latency": 0.4069, "total": 406.94 ms,
  "pd_info": {
    "prefill_ms": 52.11, "decode_ms": 344.91,
    "transfer_est_ms": 0.14, "scheduling_ms": 9.93
  }
}
```

### Benchmark — 50 prompts @ 4 QPS (Qwen-2.5-7B through P-D)
| Metric | P-D (this run) | Regular Cara @ 4 QPS (Day 2.2 low) | Δ |
|--------|------|------|---|
| TTFT P50 | 31 ms | 19 ms | +12 ms (scheduling+hop) |
| TTFT P95 | 49 ms | 27 ms | +22 ms |
| E2E P50 | 1341 ms | 1345 ms | ~0 (within noise) |
| E2E P95 | 1373 ms | 2469 ms | −1.1 s (fewer tail stalls) |
| Success | 50/50 | 50/50 | — |

**Analytical KV-transfer model check:** estimated 0.14 ms (tiny for short prompts at A30 TCP 1.67 Gbps). Measured decode_ms=345 ≈ expected 7B-on-A30 decode time. Transfer overhead negligible, as expected. Paper's analytical formula (§A.2) holds.

**Take:** P-D worked end-to-end on A30 cluster with KV transport via NIXL. The ~12 ms TTFT penalty is the scheduling + cross-host hop; paper should position this as the worst-case overhead for short prompts. For longer prompts and/or bigger models, transfer_est grows linearly — that is the interesting regime for a full sweep on Apr 26.
