## Low-λ gap is STRUCTURAL, not tunable (probe 2026-06-08 05:30)
Adaptive batch policy (cara_serve.py:221-239): busy-ratio<0.3→mbs=4/timeout=50ms, <0.7→16/100ms, else 32/200ms
(min batch already 4 at few-busy-hosts). Probe (λ6, adaptive OFF, sweep): lowering timeout cuts the scheduling
residual (sched_oh 121→73ms @ mbs1/to5) BUT e2e unchanged (~2030-2077ms) — less batching trades scheduling-wait
for higher backend latency (loses batch parallelism), and e2e is generation-bound (~1950ms). So the low-λ gap vs AvgPro
(~119ms @λ6, ~82ms @λ8, then cara wins from λ10; ~0.6% cost) is the inherent batched-scheduler setup cost
(§5.3 "shifts waiting upstream"), NOT a config knob — aggressive batching-off (mbs=1/to=5) only narrows it to
~56ms (not adoptable: kills high-λ). NOTE: 50ms = adaptive LOW-LOAD timeout (config), NOT the gap. DECISION:
don't tune; keep honest footnote. Default restored (mbs16/adaptive/100ms).
